# B6-2 실제 평가 대비 문답 (Verbal Q&A)

> 평가자가 질문할 수 있는 내용에 대해, 내가 직접 말로 설명할 수 있는 답변을 정리.

---

## 🎯 항목 1: 기능 동작

### Q1. "python main.py commit을 실행하면 어떤 일이 일어나나요?"

**A.**

네 단계로 동작합니다.

첫째, `GitCollector`가 `git status --short`와 `git diff HEAD`를 실행해서 변경된 파일 목록과 diff 내용을 수집합니다. 변경사항이 없으면 "변경 사항이 없습니다" 메시지를 출력하고 종료합니다.

둘째, `prompt_builder`가 수집된 diff를 프롬프트로 조립하는데, 이때 `sanitizer`가 항상 민감정보를 마스킹합니다. API Key나 이메일 같은 패턴이 diff에 있으면 `***MASKED***`로 치환합니다.

셋째, `ai_client`가 NVIDIA NIM API를 1회 호출합니다. `AI_API_KEY`가 설정되어 있으면 NVIDIA NIM에 요청을 보내고, `--mock` 옵션이 있으면 템플릿 기반으로 생성합니다. API Key가 없으면 에러 메시지를 출력하고 종료합니다.

넷째, 결과를 터미널에 출력하고 validator.py로 형식을 검증합니다. "초안입니다. 검토 후 적용하세요" 안내를 출력합니다.

### Q2. "변경 사항이 없을 때 어떻게 되나요?"

**A.**

"변경 사항이 없습니다. 커밋 메시지를 생성하지 않고 종료합니다."를 출력하고 return으로 종료합니다. API 호출 없이 즉시 종료하므로 비용이 발생하지 않습니다.

### Q3. "API Key가 없을 때 어떻게 되나요?"

**A.**

기본(Real) 모드에서는 에러 메시지를 출력하고 종료합니다: "[ERROR] AI_API_KEY 환경변수가 설정되지 않았습니다." 이건 과제 요구사항인 "API Key 누락시 오류 출력 및 종료"를 따른 것입니다.

`--mock` 옵션을 주면 API Key 없이도 템플릿 기반으로 커밋 메시지를 생성합니다. 이건 개발이나 테스트 환경에서 API Key 발급 전에 도구를 테스트하기 위한 용도입니다.

NVIDIA NIM를 사용하므로 API Key는 NVIDIA NIM API Key(Personal Access Token)입니다. Settings → Developer settings → Personal access tokens에서 Models 권한만 체크해서 발급하면 됩니다.

### Q4. "PR 초안은 어떤 구조로 생성되나요?"

**A.**

Why/What/How to Test 세 섹션 구조로 생성됩니다. 프롬프트에 명시적으로 지시하고 있고, mock 모드에서도 동일한 구조로 생성합니다. 출력 후 "자동 적용되지 않습니다. 검토 후 적용하세요" 안내를 출력합니다.

## 🎯 항목 2: 보안 / 민감정보

### Q5. "git diff에 API Key가 포함되어 있으면 어떻게 되나요?"

**A.**

`sanitizer.py`가 항상 마스킹을 수행합니다. 정규표현식으로 8가지 패턴을 감지합니다 — NVIDIA NIM Key, NVIDIA NIM API Key, Supabase 키, 이메일, 비밀번호, JWT 토큰, AWS 키, 전화번호입니다. 감지된 패턴은 `***MASKED***`로 치환되어 AI 프롬프트에 전달됩니다.

`--safe-mode` 옵션을 추가하면 마스킹 외에도 diff를 최대 10개 파일, 200줄로 제한합니다.

## 🎯 항목 3: AI API 설계

### Q6. "NVIDIA NIM를 선택한 이유는?"

**A.**

NVIDIA NIM는 NVIDIA NIM API Key으로 인증하는  API입니다. 이미 GitHub 계정이 있어서 PAT 발급이 간단했고, 무료(1,000 credits)에 신용카드가 불필요합니다. meta/llama-3.3-70b-instruct, Llama 3.3 70B, Phi-3 등 여러 모델을 선택할 수 있고, NVIDIA NIM SDK와 호환되어 기존 코드를 그대로 사용할 수 있습니다.

### Q7. "temperature는 어떤 영향을 미치나요?"

**A.**

temperature는 AI 출력의 무작위성을 조절합니다. 0.0에 가까울수록 결정론적이고, 1.0에 가까울수록 창의적입니다. 커밋 메시지에는 일관성이 중요하므로 0.0~0.2가 적합하고, 기본값은 0.3입니다. `--temperature` CLI 옵션으로 조정할 수 있습니다.

### Q8. "max_tokens는 어떤 영향을 미치나요?"

**A.**

max_tokens는 AI 출력의 최대 길이를 제한합니다. 너무 작으면 출력이 중간에 잘립니다. 기본값은 500이고, PR 본문 전체를 생성하려면 `--max-tokens 1000`이 안전합니다.

### Q9. "재생성과 후처리 중 어떤 것을 권장하나요?"

**A.**

후처리를 권장합니다. AI가 생성한 초안의 대부분이 좋고 일부만 수정이 필요한 경우가 대부분이기 때문입니다. 후처리는 비용이 없고 즉시 가능합니다. 재생성은 1회 실행 1회 API 호출 제약이 있어 자동화하지 않았습니다.

## 🎯 항목 4: 구조 / 설계

### Q10. "왜 6개 모듈로 분리했나요?"

**A.**

단일 책임 원칙과 관심사 분리를 위해 분리했습니다. main.py는 CLI, git_collector.py는 Git 수집, ai_client.py는 API 호출, prompt_builder.py는 프롬프트 조립, sanitizer.py는 보안, validator.py는 출력 검증을 각각 담당합니다.

### Q11. "1회 실행 시 API 호출 횟수는?"

**A.**

commit이든 pr이든 각각 1회 API 호출만 합니다. 제약사항에서 1회 실행 1~2회 이내를 권장하고 있고, 로그에 `[INFO] AI API 호출 횟수: 1`을 출력합니다.

---

## 🎯 항목 5: 제약사항 준수

### Q12. "git push나 GitHub PR 생성은 구현했나요?"

**A.**

구현하지 않았습니다. 제약사항에서 "원격 저장소 자동 반영 기능은 구현하지 않는다"고 명시되어 있습니다. 터미널에 초안을 출력하는 것까지가 목표입니다.

### Q13. "환경변수는 어떻게 관리하나요?"

**A.**

`AI_API_KEY`, `AI_API_URL`, `AI_MODEL` 세 가지 환경변수를 사용합니다. 코드에 API Key를 하드코딩하지 않고 `os.environ.get()`으로만 읽습니다. `.env.example`에 예시를 제공하고, `.gitignore`에 `.env`를 포함시켰습니다.

### Q14. "생성된 커밋/PR 문구가 완벽한 정답인가요?"

**A.**

아닙니다. 제약사항에 "생성된 커밋/PR 문구는 최종 정답이 아니며, 사용자가 검토 후 적용한다"고 명시되어 있습니다. 출력 마지막에 항상 "초안입니다. 검토 후 적용하세요" 안내를 출력합니다.
