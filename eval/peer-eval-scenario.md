
### 6-8. AI API 응답 지연 — 모델 변경으로 해결

**문제**: `llama-3.3-70b-instruct` 모델 응답에 약 3분(176초) 소요. 기존 타임아웃 30초로는 응답을 받기 전에 타임아웃 발생. 평가 환경에서 데모가 불가능한 상황.

**원인**: 70b(700억 파라미터) 모델은 추론 비용이 높아 응답이 느림. NVIDIA NIM 무료 크레딧 환경에서 우선순위가 낮아 더 느림.

**해결 과정**:
1. 타임아웃을 30초 → 180초로 늘려봄 → 일단 동작하지만 3분 대기는 UX 상 불가능
2. 더 가벼운 모델 탐색: `llama-3.1-8b-instruct` (80억 파라미터) 테스트
3. 결과: 2.7초 응답 (65배 빠름), 커밋 메시지 품질도 충분

**최종 해결**: 기본 모델을 `meta/llama-3.1-8b-instruct`로 변경
- 응답 시간: 176초 → 3초 (65배 개선)
- 타임아웃: 30초면 충분 (원래대로 유지)
- 커밋 메시지 품질: 충분 (간결하고 정확)
- 근거: 커밋 메시지 생성은 단순 요약 작업이므로 8b 모델로도 충분. 70b는 복잡한 추론에 적합.

**트레이드오프**:
- 포기한 것: 70b 모델의 더 상세한 분석 능력
- 얻은 것: 65배 빠른 응답, 평가 환경에서 실시간 데모 가능, UX 개선
- 판단: 커밋 메시지 생성에는 응답 속도가 품질의 미세한 차이보다 중요
