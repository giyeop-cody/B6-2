# 추론 기록 #04: AI API 파라미터 + 재생성 vs 후처리

> 사전평가 #6, #10, #12, #13, #15 보완

## 1. temperature 영향 (사전평가 #12)

temperature는 AI 출력의 **무작위성(랜덤성)**을 조절하는 파라미터다.

| 값 | 특성 | 적합한 용도 | 위험 |
|----|------|------------|------|
| **0.0~0.1** | 거의 결정론적 — 같은 입력에 거의 같은 출력 | 커밋 메시지 (일관성 중요) | 표현이 단조로울 수 있음 |
| **0.3** (기본) | 약간의 변형, 자연스러운 문장 | 일반적 사용 | — |
| **0.5~0.7** | 다양한 표현 | PR 본문 (설명 풍부) | 일관성 저하 |
| **0.8~1.0** | 매우 창의적, 예측 어려움 | 아이디어 브레인스토밍 | 커밋/PR에 부적합 (형태 붕괴) |

**결합도 영향**: temperature가 높으면 같은 diff에 대해 매번 다른 커밋 메시지가 생성됨 → 재현성 저하.

**CLI 옵션**: `--temperature 0.1` (결정론적), `--temperature 0.7` (창의적)

## 2. max_tokens 영향 (사전평가 #13)

| 값 | 출력 길이 | 적합한 용도 | 위험 |
|----|---------|------------|------|
| **200** | 매우 짧음 | 커밋 메시지 1줄 | 본문이 잘릴 수 있음 |
| **500** (기본) | 표준 | 커밋 메시지 + 본문 | 대부분 충분 |
| **1000** | 긴 출력 | PR 본문 (Why/What/How 전체) | — |
| **2000+** | 매우 김 | 상세 PR + 다중 섹션 | 비용 증가, 응답 지연 |

**절단 위험**: max_tokens가 너무 작으면 출력이 중간에 잘림.

**CLI 옵션**: `--max-tokens 1000` (PR용), `--max-tokens 200` (짧은 커밋)

## 3. API 파라미터 옵션화 이유 (사전평가 #10)

| 이유 | 설명 |
|------|------|
| **재현성** | 같은 diff에 대해 같은 결과를 얻으려면 temperature=0으로 고정 가능 |
| **실험성** | 다양한 temperature/max_tokens로 출력 품질 비교 가능 |
| **용도별 튜닝** | 커밋 메시지(짧고 결정론적) vs PR 본문(길고 설명적) 다른 값 사용 |
| **비용 제어** | max_tokens를 낮춰 API 비용 절감 (NVIDIA NIM 무료 한도 내) |

## 4. 재생성 vs 후처리 (사전평가 #15)

| 기준 | 재생성 (AI 재요청) | 후처리 (사용자 수정) |
|------|-------------------|---------------------|
| 정확성 | AI가 다시 분석 → 더 정확할 수 있음 | 사용자 판단 → 정확하지만 시간 소요 |
| 제어성 | 낮음 (AI가 결정) | 높음 (사용자가 결정) |
| 효율성 | 낮음 (비용 + 지연) | 높음 (즉시 + 무료) |
| 권장 | 구조가 잘못됐을 때 | 세부 수정만 필요할 때 |

**본 프로젝트 정책**: 후처리 권장 (1회 실행 1회 API 호출 제약 + 비용 효율성)
